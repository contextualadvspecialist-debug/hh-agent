# hh-agent

Агент поиска работы на hh.ru: сканирует выдачу, оценивает вакансии, подбирает резюме, пишет сопроводительное, откликается, следит за чатами и готовит ответы.

Работает в режиме «человек в контуре»: отклик уходит после нажатия кнопки в Telegram, анкеты и нестандартные вопросы остаются на ручную проверку.

## Требования

- Node.js 22.5+ (используется встроенный `node:sqlite`)
- Установленный Google Chrome
- Аккаунт hh.ru

## Установка

```bash
git clone https://github.com/contextualadvspecialist-debug/hh-agent.git
cd hh-agent
npm install

# Создайте локальные файлы конфигурации из шаблонов:
cp config.example.json config.json
cp profile.example.json profile.json

# Авторизуйтесь на hh.ru:
npm run login
```

`npm run login` откроет Chrome с отдельным профилем (`profile/`). Войдите в hh.ru один раз — сессия сохранится. Это окно агент использует и дальше, поэтому закрывать его вручную не нужно.

## Telegram-бот

1. Напишите `@BotFather` → `/newbot` → получите токен.
2. Узнайте свой `chat_id`: напишите `@userinfobot`.
3. Впишите в `config.json`:

```json
"telegram": { "token": "123456:AA...", "chatId": "123456789" }
```

Без токена агент работает, но сообщения пишет в консоль. Вместо файла можно задать `HH_TG_TOKEN` и `HH_TG_CHAT_ID` в переменных окружения.

## LLM (опционально, но сильно улучшает письма и ответы в чатах)

Подойдёт любой OpenAI-совместимый API. Пример для DeepSeek:

```json
"llm": {
  "baseUrl": "https://api.deepseek.com/v1",
  "apiKey": "sk-...",
  "model": "deepseek-chat"
}
```

Можно не писать ключ в файл: `HH_LLM_BASE_URL`, `HH_LLM_API_KEY`, `HH_LLM_MODEL` подхватятся из окружения.

Без ключа письма собираются по шаблону из `profile.json`, а ответы в чатах агент не пишет — только показывает сообщение работодателя.

Проверить всё сразу: `npm run check` — покажет, настроены ли LLM и Telegram, жив ли ключ и есть ли логин на hh.

## Команды

```bash
npm run scan              # AI-выдача, показать подходящие вакансии
npm run scan -- --direct  # плюс директ-пул (упор на Яндекс Директ)
npm run chats             # проверить непрочитанные чаты
npm run statuses          # статусы откликов из «Переговоров»
npm run digest            # сводка за день
npm run letter -- 123456  # письмо под вакансию (--resume ai|direct)
npm run apply -- 123456   # откликнуться (--resume ai|direct)
npm run block -- "ООО"    # компания в чёрный список
npm run unblock -- "ООО"  # убрать из чёрного списка
npm run check             # проверить логин, LLM и Telegram
npm run run               # демон: планировщик + Telegram-бот
npm test                  # юнит-тесты
```

В демоне доступны команды бота: `/scan` (AI), `/direct` (директ-пул по запросу), `/chats`, `/statuses`, `/digest`, `/status`, `/block Компания`, `/blocked`, `/unblock Компания`, ссылка на вакансию.

## Как это работает

1. **Поиск** — основной упор на AI-вакансии (`hh.queriesAI`). Директ-вакансии (`hh.queriesDirect`) ищутся только по явному запросу `--direct` или командой `/direct` и складываются в отдельный пул `direct-pool`. Внутри директ-пула упор на Яндекс Директ: вакансии только про Google Ads штрафуются при скоринге.
2. **Скоринг** — правила по ключевым словам (AI / реклама / минусы), штрафы за опыт 6+ лет и зарплату ниже `hh.minSalary`, плюс уточнение через LLM. Ниже `threshold` вакансия отсеивается.
3. **Резюме** — выбирается автоматически: AI-вакансии → AI-специалист, реклама → Директолог. Можно переопределить кнопкой.
4. **Чтение вакансии** — перед письмом страница вакансии открывается целиком (описание до 6000 знаков), а не только карточка из выдачи.
5. **Письмо прикрепляется к каждому отклику** — LLM пишет по полному описанию с упором на 1–2 требования из него; без LLM собирается шаблон с ротацией вступлений и фактов. Каждое новое письмо сравнивается с последними 20 (сходство по словам): при совпадении >0.8 письмо переписывается. Письма сохраняются в `letters/`.
6. **Отклик** — прямой URL формы отклика, переключение резюме через скрытый radio, вставка письма, проверка результата.
7. **Чаты** — чтение переписки через iframe `chatik.hh.ru`, регулярный бэкфилл последних диалогов, распознавание ИИ-помощников hh (без спама автоответами), мгновенные алерты на внешние опросники и анкеты (Google Forms, Яндекс.Формы), дедупликация сообщений и подготовка черновика ответа через LLM.
8. **Дедупликация** — повтор той же вакансии от той же компании (или от кадрового агентства при совпадении названия и зарплаты) в базу не попадает.
9. **Статусы откликов** — раз в `limits.statusEveryHours` агент читает «Переговоры» по вкладкам-фильтрам hh (`state=INTERVIEW`, `DISCARD`, …) и шлёт уведомление при переходах в «Приглашение» или «Отказ». Отклики, сделанные до запуска агента, при первом чтении импортируются в базу со своим статусом — они не считаются откликами «сегодня» и в дневной лимит не входят.
10. **Окно отправки** — отклики уходят только в `limits.sendWindow` (по умолчанию 10:00–19:00), вне окна очередь ждёт. Ручной `npm run apply` окно игнорирует.
11. **Дайджест** — после `limits.digestHour` (по умолчанию 20:00) приходит сводка: найдено, откликов, ждут ответа, приглашения, отказы, очередь.

## Ограничения и безопасность

- **Капча не обходится.** Агент останавливается, выводит окно Chrome на передний план и присылает кнопку «Решил, повторить». Решение — только вручную.
- **Дневной лимит** — `limits.dailyApplications` (по умолчанию 8) и пауза между откликами 90–240 секунд.
- **Автоотклик выключен** (`autoApply: false`). Включайте, только если доверяете фильтру.
- **Анкеты и вопросы работодателя** не заполняются автоматически — вакансия помечается «нужно вручную».
- Массовая автоматизация противоречит правилам hh.ru: держите лимиты низкими, не снимайте паузы.
- `config.json`, `profile/`, `data.db` содержат личные данные — не коммитьте их (они в `.gitignore`).

## Настройка под себя

- `profile.json` — факты, контакты, роли и стиль письма. Всё, что попадает в письма, берётся отсюда; выдуманных фактов агент не добавляет.
- `config.json` — `queriesAI` и `queriesDirect`, `excludeCompanies` и `excludeKeywords`, `minSalary`, порог, лимиты (`sendWindow`, `digestHour`, `statusEveryHours`, `dailyApplications`), резюме (id и название).
- `data.db` — история вакансий, откликов и сообщений. Удалите файл, чтобы начать с чистого листа.
